# P0-5 完成说明

完成日期：2026-08-05

## 完成范围

1. 普通用户不查看或切换历史版本；公网仅展示当前生效版本、数据范围和更新时间。
2. 后台历史版本、差异和回滚接口迁移到 `/api/admin/graph-releases/**`，由专业角色保护。
3. 新岗位查询发布、批量发现发布和既有岗位演化发布统一经过版本冻结、SHA-256 完整性校验、事务激活和审计记录。
4. 回滚只重新激活已冻结并通过完整性校验的版本，不删除或覆盖岗位、证据、修订和历史关系。
5. 新岗位候选补齐职级和技术栈，继续复用证据锚点、乐观锁、修改原因、操作者和前后差异。
6. 数据处理任务真实执行格式标准化、近重复、时滞、JD 通胀、事实抽取和技能归一化六个步骤。
7. 每个处理步骤记录输入数、输出数、耗时、状态、失败代码、失败原因和尝试次数；重试从失败步骤继续，不重跑已完成步骤。

## 原则应用

- KISS：普通用户只保留当前结果，不新增历史版本页面。
- YAGNI：不恢复第二套专业网站，不引入 Neo4j 或新的审核体系。
- DRY：三条发布路径共用同一个版本保护器，岗位字段沿用既有候选修订流程。
- SOLID：处理器负责单一步骤，处理服务只负责编排、状态和重试；治理服务依赖仓储抽象。
