## 当前问题与缺陷

1. **冻结集余量很小**

   主 F1 为 90.05%，只比 90%目标高 0.05 个百分点。比赛若使用不同隐藏样本，仍有跌破 90%的风险。

2. **技能召回仍然偏低**

   冻结集技能 Recall 为 **84.51%**、技能 F1 为 **88.54%**。当前总指标主要依靠职责结果拉升，新增技术词、冷门框架和跨行业 JD 仍可能漏报。

3. **盲测独立性有限**

   50 条盲测采用“AI 辅助预标注 + 人工逐条复核”，不是完全由第三方从零标注的独立盲测。97.19%可以证明复核集回放效果，但不能完全代表未知数据泛化能力。

4. **开发集复核元数据不完整**

   100 条冻结集内容和 SHA-256 已固定，但历史表格没有为每条样本完整填写“已复核”状态，因此最终评测没有启用 `--require-reviewed`；50 条盲测已启用该门禁。

5. **部分技能粒度仍依赖金标规范**

   大模型/LLM、Agent/AI Agent、稳定能力概念和具体框架之间存在粒度差异。更换评委金标规范后，可能出现成对的 FP/FN。

6. **全项目仍有一个独立测试失败**

   `ResumeSkillThirtyGoldEvaluationTest` 的简历技能 Recall 约为 **50.89%**，未达到其 90%要求。该问题属于简历技能提取，不是 JD 解析，但如果比赛验收整个网站，会影响整体结论。

7. **工作区尚未整理**

   当前存在大量未提交修改、历史评测缓存、日志和临时构建目录。它们不影响正在运行的网站，但会增加打包、迁移和现场恢复风险。尚未执行 Git 提交或批量清理。

## 比赛前建议

- 再准备一批由人工从零标注的隐藏 JD，复测未知数据表现。
- 优先补充有明确原文字面的高频漏报，不放宽 AI、Agent、Go 等短词门控。
- 固化当前 Docker 镜像、评测报告、金标文件和 SHA-256，准备现场快速恢复方案。
- 如果比赛同时验收简历解析，应将简历技能提取作为独立任务继续修复。

## 准确表述

当前可以表述为：**JD 职责解析已通过当前 90%下界门槛；JD 技能与综合指标仍未达到正式门槛。系统已具备更严格、可复现的评测流程，但还需要新的独立人工金标集完成最终验证。**
