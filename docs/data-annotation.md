# 正式数据与标注规范

## 1. 数据模式

- `REAL`：合法获得、具有来源台账的真实数据，可进入分析语料。
- `DEMO`：合成或演示数据，只能用于界面和流程演示。
- `FROZEN_CACHE`：固定输入对应的冻结模型结果，只能用于离线演示。

任何正式评测脚本必须默认排除 `DEMO` 和 `FROZEN_CACHE`。

## 2. 数据集隔离

- `development`：开发 Prompt、词典和规则。
- `validation`：选择阈值、权重和模型。
- `test`：最终冻结，不参与任何调参。
- `golden-regression`：模型或 Prompt 变化后的快速回归。

同一原始文档及其近重复版本不能跨数据集，避免数据泄漏。

## 3. JD 来源台账字段

每条 JD 至少记录：

```text
document_id, data_mode, source_name, source_type, source_url,
license_status, collection_method, collected_at, published_at,
company_name, job_title, city, industry, level, content_hash
```

未取得再分发许可时，提交包只保留必要的脱敏片段、哈希和来源说明。

## 4. JD 标注字段

- 标准岗位名称与职级。
- 核心职责及原文位置。
- 技能原词、标准词、必备/加分/否定和原文位置。
- 行业场景、学历、经验和薪资字段。
- 无法判断时使用 `UNCERTAIN`，不得强制猜测。

## 5. 简历标注字段

- 教育、专业、毕业时间。
- 技能原词、标准词和证据等级 L0-L4。
- 项目、实习、课程和证书证据及原文位置。
- 姓名、电话、邮箱、住址不进入匹配标签。

## 6. 匹配标注

每个简历-岗位版本对由标注者独立给出：

- `READY`：具备多数必备能力和足够实践证据。
- `NEAR_READY`：存在 1-3 项关键可补足缺口。
- `NOT_READY`：存在多项关键缺口或核心门槛风险。

同时标注关键优势、关键缺口和硬门槛，不只标一个总标签。

## 7. 标注流程

1. 本人和两名协助者独立标注。
2. 三人至少两人一致时形成初步标签。
3. 重大分歧由指导老师或领域教师裁决。
4. 先计算一致性；一致性不足时修改规范并重新标注。
5. 测试集冻结后生成版本号、文件哈希和冻结时间。

## 8. 指标

- JD 解析：字段 Accuracy，技能/职责 Precision、Recall、F1。
- 简历提取：字段 Accuracy，技能和证据等级 Precision、Recall、F1。
- 人岗匹配：Accuracy、Macro-F1、混淆矩阵和标注一致性。
- 三项指标均报告样本量和 95% Bootstrap 置信区间。
- 人工修正后的结果不得计入自动提取准确率。

## 9. 禁止事项

- 不使用最终测试集补词典或调阈值。
- 不用重复 JD 扩大样本量。
- 不将 DEMO 数据混入正式指标。
- 不因期望结果修改标注标签。
- 不公开真实简历中的个人身份信息。
