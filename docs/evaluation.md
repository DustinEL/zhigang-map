# 评测口径与结果

## 1. 原则

- 报告必须带样本量、指标定义和口径，不只写一个百分数。
- 开发集、已见回归集、独立盲测集分开；不能把调参集结果当作泛化指标。
- 旧报告与当前代码不一致时，以当前代码 + 冻结样本的结果为准。
- 没有测过的指标写“未测”，不补数字。

## 2. 当前可复现结果

### JD 解析

| 指标 | 结果 | 口径 |
|---|---:|---|
| 技能 + 职责综合 F1 | **88.15%** | 100 条人工金标，已见回归集 v30 |
| 技能 F1 | **85.96%** | 同上；Precision 86.43%，Recall 85.50% |

## 3. 评测方法

JD 解析采用实体级微平均 F1：

- 岗位名称、技能：精确匹配；
- 职责：字符二元组 Jaccard 相似度 ≥ 0.62 的一对一匹配；
- 技能 + 职责：合并后的 micro-F1；
- 置信区间：按整条 JD 重采样的 bootstrap。

简历解析、匹配的指标定义见 [data-annotation.md](data-annotation.md) 和 [design/resume-matching.md](design/resume-matching.md)。

## 4. 已知问题

1. 100 条金标既用于开发又用于评估，88.15% 是已见回归集结果，不代表未知 JD 的泛化性能。
2. 技能漏报仍是主要瓶颈，常见漏报包括 SQL、模型微调、分布式系统、Go、MCP 等。
3. 技能粒度不统一：Kafka 与“消息队列”、Spring Cloud 与 Spring、LLM 与“大语言模型”是否同时输出，需要标注规范约束。
4. 50 条旧盲测的 97.19% 不能作为独立泛化证据。
5. 人岗匹配的少数类支持数不足，不能宣称 90%。
